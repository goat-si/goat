Fleet goals

A fleet goal tells GOAT what should be true, such as “these pull requests are merged” or “each worker reported a result”, and GOAT keeps working toward it. It starts the worker threads the goal asks for, sends a short follow-up when a worker finishes without getting there, and stops when every condition holds. Goals are off until you turn them on.

Turn goals on

Goals do nothing until the server setting fleet.controllerEnabled is on. Turning it off again stops every goal on the next check without touching running threads.

Declare a goal

An agent running inside a GOAT thread declares a goal with goat_call {path:"goal.apply"}. The goal then acts as that thread: workers never get more access than the thread had when it declared the goal, and later updates can only lower that.

Workers run on this machine unless the goal names SSH hosts in workers.hostSelector.hosts or puts its project on another host (spec.project.host). Workers on another host need an owner with full access and the project’s folder there: spec.project.cwd, or a projectId on that host. A worker on another host whose run fails, or whose host stays unreachable, moves to another host the goal allows; until GOAT can tell whether a move started, its slot waits instead of starting a second worker. Draining a host (goat_call {path:"host.drain"}) moves the goal workers on it to other hosts the goal allows, one worker per goal at a time and only between runs, so a running turn is never interrupted. A moved worker starts again from its pushed branch, or from the goal’s base branch when nothing was pushed; anything it did not push stays on the drained host. A worker that cannot move, because no allowed host can take it or it is on its last attempt, stays where it is and its goal says why. A worker that only waits for its pull request to merge stays until it needs another turn. Uncordoning the host stops further moves.

An agent outside GOAT can declare a goal too, with its MCP sign-in or a client token approved for more than read-only access. The goal then acts as that client and is capped by the access it was approved with. It stops acting while the client’s session is revoked or expired, so a goal that should outlive a token needs a token that lasts as long.

This goal starts two workers, each on its own branch from dev, and is done when the pull requests they open are merged and each has reported its result:

{
  "title": "Fix the flaky server tests",
  "clientRequestId": "flaky-tests-2026-10-20",
  "spec": {
    "kind": "pr_bundle",
    "project": { "host": null, "projectId": "<your project id>", "cwd": null },
    "repo": "goat-si/goat",
    "targets": [{ "type": "prompt", "key": "flaky", "text": "Make the flaky server tests pass." }],
    "workers": {
      "count": 2,
      "modelSelection": { "instanceId": "codex", "model": "gpt-6.1-sol" },
      "runtimeMode": "full-access",
      "promptTemplate": "{{target}} Work on branch {{branch}} and open a pull request.",
      "workspace": { "baseRef": "dev", "branchPrefix": "goal/flaky", "startFromOrigin": true }
    },
    "doneWhen": [{ "type": "pull_requests_merged" }, { "type": "thread_reported_result" }]
  }
}

Retrying with the same clientRequestId returns the same goal. To change a goal, apply it again with its id. Pass dryRun: true to check a spec without saving it.

Follow a goal

The goal.get path shows a goal’s phase (pending, progressing, blocked, degraded, succeeded, failed, paused or deleting), its workers and their threads, and its recent events, which say what GOAT did and why. goal.list lists the goals you declared, from your thread or your outside client.

Each worker run gets at most one follow-up: when CI fails on its pull request, or when it finished without opening a pull request or reporting. A run a person interrupted is left alone. A goal stops and asks for a person when it reaches its limits (by default 3 workers, 3 attempts each, 40 runs and 24 hours).

Pause, resume, or delete

goal.pause stops GOAT from acting on a goal until goal.resume. goal.delete interrupts the goal’s running workers and then removes it; force: true removes it at once. Threads, worktrees and branches always stay. Only whoever declared a goal, or a GOAT thread with full access, can pause or delete it; an outside client sees and changes only its own goals.
