Hub

A hub is one GOAT environment that runs your fleet. It is the GOAT server your phone pairs with, and its machine is also the OpenCodex Home that holds every provider sign-in, so your other machines reach their models through it. GOAT shows whether each linked device really uses the hub, and holds cloud runs there.

The hub is off until you turn it on. Make only one environment the hub.

Hub settings live in three places. Settings → Hub turns the hub on and lists Hub devices: the machines the hub reaches for phones and agents, each with whether it is linked to the hub’s OpenCodex. It shows the environment you select at the top of Settings. Settings → Connections pairs your phone. Settings → Providers → Codex chooses whether Codex uses OpenCodex Home.

When the desktop app first finds OpenCodex on its machine, it asks once whether Codex there should use your OpenCodex Home or keep its own sign-in, and, on a Home or a machine not yet linked to one, whether to turn on the hub and permission profiles. It asks one question per launch, and closing a question leaves everything as it was. Change these answers later in Settings → Providers → Codex and Settings → Hub.

Turn it on

Open Settings → Hub on the machine whose OpenCodex is the Home, and turn on This machine is the hub. GOAT then checks every linked device every 30 minutes. Checking only reads: it never changes a device or its OpenCodex settings. Cloud runs chooses whether Claude Cloud, Cursor Cloud and Devin Cloud runs start on the hub or wherever a sign-in exists.

Accounts and keys stay in OpenCodex; open its dashboard from Accounts and keys.

GOAT Connect is coming soon. Its account-wide standing consent and sign-out/sign-in workflow are described in Reach every machine through one hub.

Add, repair, or remove a device

In Settings → Hub → Hub devices, Add device to hub joins a machine to the hub’s OpenCodex by its SSH alias; a standalone device in the list has Join too. The device needs OpenCodex and a direct SSH alias on the hub. On a fresh Linux or macOS machine, the server installer’s --opencodex option installs both; installing does not join the hub. GOAT compares the host key OpenCodex is offered with the key GOAT pinned for that alias, links the device, and checks its parity.

A Windows device joins as a Hub client until your GOAT includes an OpenCodex release with Windows Remote Link support. A Hub client needs this hub’s OpenCodex in Hub mode with addresses the device can reach, such as behind Tailscale Serve. GOAT creates a single-use invite on the hub and GOAT on the device redeems it; you never see or copy the code. Agents can request the same for a device GOAT reaches only by password. With Windows Remote Link support, Windows x64 machines join as Remote Link Children over OpenSSH and Windows PowerShell, without Git Bash. PowerShell there must run in Full Language mode; setup stops and says so otherwise.

A cloud machine this hub creates joins by itself while Join new cloud machines in Settings → Hub is on, as it is unless you turn it off. GOAT installs an OpenCodex release it has tested there, without Node or npm, or keeps a supported one that is already installed. It starts OpenCodex, links it as a Remote Link Child using the host key it pinned when it created the machine, installs Codex, and adds a Codex instance that uses the hub’s accounts without a sign-in on that machine. Use Repair if the link breaks later. Turning the switch off stops new joins, even one already being set up; machines that are linked stay linked.

An SSH host you added joins only when you turn on Join as OpenCodex Child after each SSH setup on its row in Hub devices, on desktop, web or the mobile app. GOAT then sets it up right away and again after each successful SSH setup of that host, and links it only with the host key GOAT pinned when you added it. The switch is your standing permission, so only a session that can change settings turns it on; agents cannot. It turns itself off when you forget or add the host again, and when the session that turned it on signs out, expires, or loses settings permission; the row then says so. Turning it off never removes the host from the hub: use Leave for that.

The hub and a Child can run different OpenCodex versions; a Child needs 2.66.0 or later. Provider accounts stay on the hub, and every Child shares its quota. Fleet shows a Child’s quota under the hub’s pool. A host that does not report which of its instances use the pool, such as one on an older GOAT, is matched by provider and marked inferred; update GOAT there to see its actual routing.

A linked Child is Ready only after one small model request from its Codex instance succeeds through the hub, and that request counts against the hub’s quota. Until then, its row in Hub devices, in the mobile app, and in Fleet shows the step setup reached or why it stopped, with what to do next. For example, a Child whose OpenCodex release cannot prove it holds no sign-ins of its own asks you to update OpenCodex there. Agents read the same from its goat_host_status entry. Checking status never sends a model request. Changing the Child’s Codex instance, its settings, or its link to the hub clears Ready until setup verifies it again. GOAT retries setup after each successful SSH setup of the host. Continue setup on the device’s row, or an agent with goat_hub_device_setup, retries or finishes it, including on a Child linked before setup existed. Claude Code, OpenCode, and Pi use the hub only when you route them there; see OpenCodex Home.

Repair walks the fixes for failing checks in order: sync the device’s settings, restart its OpenCodex once nothing runs there, and reconnect the link. Leave disconnects the device and returns it to its own sign-ins, then revokes its link or Hub key on the hub; GOAT asks before it does that.

Sync OpenCodex models

Sync OpenCodex loads OpenCodex’s current models into Codex, on the hub first and then on each linked Child. Find it in Settings → Hub → OpenCodex models, next to Hub on the Fleet page, and under Update → Runtimes. The dialog shows what each machine will do, then its progress and result.

A Child always takes the hub’s models and settings, never its own providers, so GOAT syncs it only while it is linked to this hub; a Child that is not linked is skipped with a pointer to Repair. Codex restarts to pick up the models only on a machine with nothing running. On a busy hub the models are written, but Codex keeps its old list until it restarts or you sync again once the work finishes; a busy Child is skipped until you sync again. GOAT also syncs each machine right after a managed OpenCodex update moves it.

Each action lists its steps and their results. Some changes wait for a person: a host key GOAT has not pinned or that changed, re-linking a device, or removing one that could not be cleaned up. They appear in Settings → Decision Inbox; answer there, then select Continue on the device. Approving needs permission to change this hub’s settings.

Permission profiles

Permission profiles is off by default, and when you turn it on an agent without its own profile gets the widest built-in profile, owner, until you pick a narrower Default profile. With it on, GOAT refuses an agent’s request to launch or steer threads, work on other machines, manage the fleet or change settings when its profile does not allow it. Agents allowed to create worktrees, such as those under worker and manager, can also add and clone projects; changing or deleting a project still needs permission to change settings. Pull requests are opened and merged from the agent’s own terminal, which profiles do not control; GOAT only refuses to start a merge manager for an agent whose profile cannot merge. A supervisor whose own profile allows merging can still start one for a thread that cannot merge, unless the limits that thread was started with, such as ones forwarded from another machine, leave merging out. Turn it on in Settings → Hub.

The switch covers your whole fleet. Turning it on or off on one machine does the same on every host connected to it, and the most recent change wins wherever you made it. The row lists each host as applied, waiting (not reached yet) or needs a GOAT update; a host on an older GOAT cannot take the setting, and agents cannot launch new threads on it while profiles are on. Follow-up messages to threads already running there are still delivered, as they are to a host that is still waiting, so your agents can keep steering their work. The agent is told each time its limits may not apply on that host yet.

Read a device

Each device shows how it joined (Remote Link Child, Hub client, or standalone), its parity, its OpenCodex version, and the Home’s tunnel to it. Parity is ok when the hub serves the device’s requests and its settings match, degraded when traffic works but something on the device still describes the device, broken when requests do not reach the hub, and unproven when the device cannot say which Home served it. Verify checks one device now.

Use this device’s own sign-in when the hub is down is off by default. With it off, goal work on that device pauses while it cannot reach the hub. The setting is stored on the device, so it works while the hub is down; to change it, GOAT needs a connection to that device. OpenCodex must allow it too: the row says whether it does, or unknown when your OpenCodex does not report it yet.

Fleet shows the same devices in its Hub entry. Select its count to see each one.
