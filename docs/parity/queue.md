# Queue and queued-message parity

This brief covers app-owned queued runs, queue MCP operations, promotion, queue draining and the queue-relevant part of recovery. It distinguishes a rejected orchestration command from a provider declining an already admitted steer; replay scenarios describe semantic observations, not literal v1 domain-event names.

Pinned v1 commit: `916b5ccc1b2b6d4ecd991ab1573172bab8fb1cc4` (`/tmp/goat-v1-916b5cc`).

## Rules

1. **R1 — Queue representation.** A queue entry is a run with `status === "queued"` linked by `userMessageId` to a conversation message; it can also have a pending user-message turn item, root node and attempt. A cancelled entry remains a historical run but is no longer a queue entry. **OBSERVED** — `apps/server/src/mcp/toolkits/thread/handlers.ts:28-55`, `apps/server/src/orchestration-v2/Orchestrator.ts:8527-8547`, `apps/server/src/orchestration-v2/testkit/fixtures/queued_turn/codex_output.ts:20-48`, `apps/server/src/orchestration-v2/testkit/fixtures/queued_cancelled_while_active/codex_output.ts:12-31`.

2. **R2 — List and read.** `queue.list` returns queued run IDs and up to 1,000 Unicode code points of text, plus `truncated`, in delivery order, with live offset pagination (default 20, permitted 1–100). `queue.read` returns up to 16,000 code points; a missing, no-longer-queued or message-less entry yields `invalid_request` / `The queued message was not found.` **OBSERVED** — `apps/server/src/mcp/toolkits/thread/handlers.ts:28-55`, `apps/server/src/mcp/toolkits/thread/handlers.ts:363-389`, `apps/server/src/mcp/toolkits/thread/tools.ts:89-112`, `packages/contracts/src/agentSurface/entries/queue.ts:4-31`.

3. **R3 — Order and holds.** Delegated-completion messages precede ordinary queued messages regardless of position; within priority class the sort is `queuePosition ?? ordinal`, then ordinal. Automatic draining selects the first entry not marked `queueHeld`; listing itself includes held entries. **OBSERVED** — `apps/server/src/orchestration-v2/QueuedRunOrder.ts:3-31`, `apps/server/src/orchestration-v2/QueuedRunOrder.ts:39-42`, `apps/server/src/orchestration-v2/QueuedRunOrder.test.ts:5-49`, `apps/server/src/mcp/toolkits/thread/handlers.ts:363-375`.

4. **R4 — Intake selection.** With `deliveryIntent: auto` and no active run, start immediately; with an active run preparing/starting or outside a running provider turn, queue. Otherwise auto chooses native steer, then queue, then interrupt/restart in capability order; native maintenance targets and providers unable to steer or restart queue instead. Explicit mode and cross-thread agent send have additional rules and must not be reduced to a global default. **OBSERVED** — `apps/server/src/orchestration-v2/CommandPolicy.ts:176-199`, `apps/server/src/orchestration-v2/CommandPolicy.ts:227-267`, `packages/contracts/src/agentSurface/entries/thread.ts:236-245`, `packages/client-runtime/src/operations/commands.ts:731-770`.

5. **R5 — Drain.** On run end, the orchestrator requeues unread steers then attempts the next eligible queue entry under the thread lock. It refuses to start when the store disallows it, the thread is archived/deleted, or another blocking run exists; starting changes the queued run to `starting` and clears its queue position. **OBSERVED** — `apps/server/src/orchestration-v2/Orchestrator.ts:1145-1175`, `apps/server/src/orchestration-v2/Orchestrator.ts:1692-1699`, `apps/server/src/orchestration-v2/Orchestrator.ts:12919-12938`, `apps/server/src/orchestration-v2/testkit/fixtures/queued_turn/codex_output.ts:20-48`.

6. **R6 — Settlement is a separate operation.** `settleAfterRun` waits for follow-up automatic runs, with held queued work treated differently from runnable queued work; user follow-up and later steers can prevent this auto-settle path. Do not equate a thread's settlement with the scheduling of its next queued run. **OBSERVED** — `apps/server/src/orchestration-v2/ThreadSettlementAfterRun.ts:25-95`, `apps/server/src/orchestration-v2/ThreadSettlementAfterRun.ts:120-143`.

7. **R7 — Edit.** Edit requires nonblank text and a still-queued run with a message; otherwise errors include `Queued run <id> cannot be edited to an empty message.`, `Run <id> is not queued.`, or `Queued run <id> has no user message.` Automatic completion/notification and guest messages are rejected; the message is updated, and its corresponding user turn item is updated if present. MCP exposes text only and preserves attachments; the web command can supply replacement attachments. **OBSERVED** — `apps/server/src/orchestration-v2/Orchestrator.ts:8873-8958`, `apps/server/src/mcp/toolkits/thread/tools.ts:113-120`, `packages/client-runtime/src/operations/commands.ts:1104-1127`.

8. **R8 — Agent slash-command restriction.** MCP edit refuses text whose left-trimmed value starts `/` unless the existing message was created by an agent; its error code is `capability_denied` and explains that an agent cannot turn a person's queued message into a slash command. **OBSERVED** — `apps/server/src/mcp/toolkits/thread/handlers.ts:391-419`, `apps/server/src/mcp/toolkits/thread/handlers.test.ts:391-410`.

9. **R9 — Cancel.** Cancel requires the run still be queued, otherwise `Run <id> is not queued.`; cancellation marks the queued run rather than interrupting the currently active run. A delegated-completion entry disposes its cohort's pending automatic deliveries, and cancellation also settles a recovery-park notice. **OBSERVED** — `apps/server/src/orchestration-v2/Orchestrator.ts:8811-8856`, `packages/contracts/src/agentSurface/entries/queue.ts:63-74`, `apps/server/src/orchestration-v2/testkit/fixtures/queued_cancelled_while_active/codex_output.ts:12-41`.

10. **R10 — Reorder.** Move a queued run before another or to the end with `beforeRunId: null`; it rewrites only positions that changed. Missing/nonqueued moving or target runs produce `Run <id> is not queued.` or `Queue target <id> is not queued.`; automatic/notification deliveries cannot be moved and an ordinary entry cannot precede delegated completion. Moving before itself is rejected as target not queued after removal. **OBSERVED** — `apps/server/src/orchestration-v2/Orchestrator.ts:8725-8808`.

11. **R11 — Promotion guards.** Normal promotion requires a queued run with message, root and attempt; rejects automatic deliveries, held agent entries and fresh-context entries. A missing/nonqueued source reports `Queued run <id> is not queued.`; missing execution state, held state and fresh-context each have explicit errors. **OBSERVED** — `apps/server/src/orchestration-v2/Orchestrator.ts:8495-8565`, `apps/server/src/orchestration-v2/Orchestrator.ts:8610-8617`.

12. **R12 — Active target and atomic refusal.** Normal promotion requires a target run with root, status `running`, no effective Stop, a provider session and a running provider turn; errors name the missing or nonsteerable target. Although cancellation events are staged before steering validation, a rejected dispatch leaves the source queued and sends no steer, as the Stop race test confirms. **OBSERVED** — `apps/server/src/orchestration-v2/Orchestrator.ts:4184-4267`, `apps/server/src/orchestration-v2/Orchestrator.ts:8649-8704`, `apps/server/src/orchestration-v2/SteeringCompletion.integration.test.ts:1151-1202`.

13. **R13 — Promotion success and exceptions.** Ordinary promotion cancels the source run with termination cause `queued_replaced`, and cancels its attempt and node and forwards the same message text, attachments and author to the active turn; provider policy can instead use interrupt/restart. Target compaction and supported `/goal` take special stop/reorder paths, not ordinary steering. **OBSERVED** — `apps/server/src/orchestration-v2/Orchestrator.ts:4415-4434`, `apps/server/src/orchestration-v2/Orchestrator.ts:8576-8609`, `apps/server/src/orchestration-v2/Orchestrator.ts:8618-8722`, `apps/server/src/orchestration-v2/SteeringCompletion.integration.test.ts:1072-1098`, `apps/server/src/orchestration-v2/SteeringCompletion.integration.test.ts:1104-1145`.

14. **R14 — Provider decline differs from command refusal.** An asynchronously declined steer can be persisted as an undelivered queued follow-up; it is not displayed as delivered, and a prior Stop holds it until user action. This is distinct from R12's rejected promotion and means a blanket claim that every v1 provider refusal sends nothing *and never queues* would be false. **OBSERVED** — `apps/server/src/orchestration-v2/SteeringDeclined.integration.test.ts:94-118`, `apps/server/src/orchestration-v2/SteeringDeclined.integration.test.ts:250-267`, `apps/server/src/orchestration-v2/SteeringDeclined.integration.test.ts:272-323`.

15. **R15 — Receipts and reconciliation.** The six queue MCP schemas expose neither `clientRequestId` nor revision; the four mutation handlers allocate a new command ID when they dispatch; list and read directly read the queue. Underlying orchestration command receipts replay the same command ID and reject previously rejected IDs or cross-thread conflicts, while a new queue MCP call re-evaluates current state; use list/read and thread history to reconcile uncertain outcomes rather than assuming client-key deduplication. **OBSERVED** — `apps/server/src/mcp/toolkits/thread/tools.ts:89-135`, `apps/server/src/mcp/toolkits/thread/handlers.ts:58-66`, `apps/server/src/mcp/toolkits/thread/handlers.ts:363-449`, `apps/server/src/orchestration-v2/Orchestrator.ts:12545-12585`, `packages/contracts/src/agentSurface/entries/queue.ts:4-130`.

16. **R16 — UI equivalence.** Web drag dispatches reorder; Send Now uses explicit queued-run start when the queue can start, otherwise promotion into the active run. Client operations dispatch the same edit/cancel/reorder/promotion commands; v1 promotion uses a resending dispatcher; GOAT 2’s screen outbox has no automatic resend (`goat2-design/prd-src/decisions.md:72`). **OBSERVED** — `apps/web/src/components/chat/QueuedRunsControl.tsx:208-250`, `packages/client-runtime/src/operations/commands.ts:1050-1090`, `packages/client-runtime/src/operations/commands.ts:1104-1127`.

17. **R17 — Recovery queue boundary.** Recovery puts eligible unaccepted saved user/unattended messages back into a held queue ahead of already queued entries, restores their pending input items, and holds non-buffered queued runs. Buffered provider notifications are handled separately; unattended restored messages get a warning requiring a decision. Other restart outcomes belong to the restart lane. **OBSERVED** — `apps/server/src/orchestration-v2/RecoveryUnstartedQueue.ts:25-41`, `apps/server/src/orchestration-v2/RecoveryUnstartedQueue.ts:42-130`, `apps/server/src/orchestration-v2/RecoveryUnstartedQueue.ts:134-166`.

## Parity scenarios

The traces below are **INFERRED** planned projections, not executed replays. They omit incidental events and use `T` for one thread. Queue-change operations refer to semantic state transitions, not Part 1 event names. The v1 MCP operations in these scenarios map to UI commands in GOAT 2; MCP `queue.*` is deferred. The `input.changed` projection is pending lane C. `goat2-design/prd-src/decisions.md:73`.

Target-specific expectations. The traces are the **v1** expectations.
