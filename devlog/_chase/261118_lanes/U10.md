## C4 compatibility and denied cases

- n70, WSL folder drop. Add an optional preload method with a dedicated main-process IPC channel. Older web retains its existing drop behavior on a newer desktop/backend. New web supports native-local drops on old preload. WSL drops show a conversion error when either the preload method or main handler is missing. Main accepts only the trusted top frame, resolves a running managed WSL backend and refuses unknown/disabled backends, invalid Windows paths, and a different UNC distro. Web rejects remote and SSH destinations before IPC and discards conversion results after a draft switch or unmount.
- n117, native menu origin. Add an optional field for mouse or keyboard. Old preload calls new main without the field and uses the existing popup behavior. New web works with old preload, which ignores the third argument. An older IPC decoder ignores the additive field. Browser fallback and link permissions stay on their existing paths. Invalid origin and unauthorized IPC senders are refused.
- n923, Finder drag. Add a macOS-only optional preload capability. Old renderer has its existing click/context actions. New renderer without the method leaves native drag unavailable. Main verifies the trusted top frame, the bundled native primary environment identity, and a device-local absolute path to an existing regular file before handing it to Electron. Reject remote environment IDs, unsupported platforms, invalid/missing files and foreign sender surfaces. No new network API or remote filesystem authority.
- These three rows store no new state. Upgrade and rollback need no migration or cleanup. Web and Electron share the renderer; mobile, providers, and MCP have no entry points for these IPC methods.

Launcher proof is the guarded whole externalLauncher test file from apps/server; web routing and desktop method tests run whole at repo root, followed by the integration-base changed check.
