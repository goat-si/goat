# U11

## C4 compatibility before code (#16 and #937)

- The public change is additive: optional `pendingBackgroundTasks[].runId` in `packages/contracts/src/orchestrationV2.ts`. An older client can decode the provider-thread payload using Effect Schema's default excess-property handling and continues to read the existing roster and task status. A newer client accepts an older server's roster without the owner. No new RPC method, permission, or provider-native protocol field.
- Upgrade reads the existing JSON as-is. Both projection paths keep a task's first known owner and stamp new entries with the event run when available. An entry already observed without an owner stays unstamped on subsequent full-roster updates. No backfill or migration is needed. On rollback the prior schema discards the extra field and keeps the roster readable.
- Negative cases: an unrelated run's work, an unstamped entry, unawaited commands or monitors, and Monitor progress cannot hold or open a follow-up. Terminal provider wakes may continue the matching open follow-up. Cancellation keeps its existing path; restart holds and original delegated-task waiting stay in force. Late or duplicate wakes/reports must not reopen settled tasks.
- Server boundaries: Claude/Codex adapter events, event-to-SQL and in-memory projection, orchestrator completion and MCP reads, and GOAT question escalation. Web/desktop/mobile share these updated contracts and can consume existing notices and task states. Remote explicit reports retain their existing path. No new UI entry point, setting, schema migration, or docs workflow.
- Verify with regression-first focused tests in the existing adapter, routing, projection, queue and delegated completion files, full changed test files from the repository and again from apps/server with GOAT_TEST_TMP_GUARD=fail, then the changed-files gate. Coordinator owns independent C4 review before landing.
