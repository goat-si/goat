# U16 — Desktop and server preview control (2/2)

## C4 compatibility recorded before implementation

- #430 Electron IPC. Older renderers and hidden/crashed guests can omit the draw report, with the host using its bounded capture fallback. Newer renderers feature-detect the optional bridge method and use the existing capture path with older main processes. Reports must come from the tab's owning renderer and current guest. Stale or missing reports cannot authorize input, transfer ownership, or keep a detached capture alive.
- #450 Snapshot transport. Missing mode retains the image path. Metadata-only is selected by the server for its own managed browser, so a new server keeps the established frame capture protocol with an older desktop and screen-code still requests images. Image/save calls require frame bytes. Preserve deadline stages and reject unavailable dimensions consistently with the existing capture error path.
- #631 HTML preview assets. New servers accept the enumerated media extensions only through the existing scoped preview token and workspace root checks. Older clients use ordinary relative HTML media URLs. An older server retains its existing rejection for these extensions. Exercise unsupported types and invalid or escaping asset paths.
- These rows require no persisted-state upgrade or rollback and allocate no migration IDs.
