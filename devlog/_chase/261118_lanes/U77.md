## Compatibility and safety

C4 compatibility note was sent before code on 142/191/214/328/367/408/442/483. No migration was added; IDs 167–174 were reserved by the coordinator. #142 uses private Git objects and publishes before refs; on macOS it uses per-object fsync because batch fsync nested an object store and broke bulk pack publication in the regression fixture. This can add capture I/O cost. Internal storage errors map to existing `VcsProcessExitError`: checkpoint capture, WebSocket `vcs.init`, `review.getDiffPreview`, `review.getDiffFileContents`, and MCP scoped diff preview and file contents. The two MCP paths wrap failures as `OrchestratorMcpFailure` with the safe stage message. Contract `packages/contracts/src/vcs.ts` is unchanged against the integration parent; older clients receive an existing tag. New clients against older servers receive existing tags; unsafe operations continue to deny or retain on unknown state. A persisted snapshot for a moved project records the owning repository as its workspace root; no schema migration is needed. Existing refs and both GOAT/T3 aliases remain supported. If the older repository disappears, its snapshot remains unavailable rather than being redirected to another clone.

#442 uses tombstones, retained live/archived fork ancestry, pending/running outbox exclusion, scoped namespaces, ordinal-only ref selection, `--no-deref` and object-id compare-and-swap. On listing over the 16 MiB bound it retains refs; unresolved repositories and errors log and retry on later hourly/manual sweeps. Deletion notifications request a bounded/coalesced worker sweep, independent of worktree-deletion settings. #483 retains on dirty/untracked/deinitialized local files, unresolved Git metadata or unpushed submodule history. Reachability currently uses remote-tracking refs conservatively; it does not additionally allow the optional surviving main module object-store route.
