## C4 compatibility notes (before implementation)

- #261: Existing launch inputs and progress/claim output remain identical in both client/server pairings. Modern Git owns an add registration through its unique lock reason, and abort cleanup must preserve foreign paths and reused branches. Older Git keeps its supported add path and conservative rollback. A durably claimed worktree belongs to launch recovery. No migration. A crash can leave a Git registration on disk, so ownership proof must remain readable by ordinary Git.
- #558: Existing launch and submodule settings work across versions. Recovery applies only to an owned fresh checkout and successfully cloned submodules. Missing clones keep their original diagnostic. Missing, uninitialized, reused or edited paths are negative cases. Interruption propagates. No migration or config rewrite. An older server can use the resulting ordinary Git worktree.
- #989: Skipped per d1. GOAT and legacy project file schemas and sparse-exclude precedence remain compatible both ways. Unsupported pattern-file input adds no new effect. No stored-state change or upgrade/rollback step.
- #1083: Existing restore request/result and on-disk markers remain readable across versions. Under the existing subtree lease, a locked Windows cwd may keep its outer folder while known leftover entries move to a sibling. A linked checkout, unexpected files, and a failed partial move must preserve the files; recover or report the sibling on failure. No migration. Set-aside files remain ordinary files if the server is rolled back.
