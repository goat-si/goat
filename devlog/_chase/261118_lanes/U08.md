# U08 · Desktop and server preview control

## C4 compatibility decisions recorded before implementation

- **105 · Snapshot deadlines.** Keep the existing timeout tag, request, and response envelope. Add a bounded optional list of known snapshot stage names. Older consumers still receive the existing timeout fields and can ignore the new field. New consumers accept an old timeout with no detail and retain the broker deadline. For remote timeouts, bound the reported duration by the outer request deadline, reject malformed, oversized, or unknown stage lists, and preserve the legacy error for denied control and file requests. Timeout diagnostics contain stage names only. Successful JSON, metadata-only responses, and screenshot bytes retain their existing shapes. No persisted state changes. Rollback drops the optional diagnostic.
- **369 · Empty Chromium jar.** Cookie import stays on the existing desktop IPC request, permissions, key path, and result shape in both version directions. A newer desktop reports zero cookies for a valid SQLite jar with no cookie table. An older desktop reports its existing read error for the same jar. Key acquisition, unreadable or invalid database errors, and Firefox counting retain their current paths. Probe the copied snapshot schema before reading cookie or version rows. No source profile writes or migration. Rollback restores the previous error for a razed jar.

## P1 verification surfaces

- Desktop and web preview should retain the tab on a renderer crash, navigate away from a stuck script, update the title and native address without an extra navigation, preserve popup appearance and reopened zoom, and keep the native guest alive until close completes.
- Desktop Settings should open the main window with a preview popup focused. Hidden screenshots should save after the paint probe, recordings should have distinct paths, and a slow stream consumer should receive the newest frame once it catches up. Chromium import should show zero for an emptied jar.
- A mobile or remote viewer should continue to consume the server-rendered tab's status and stream. The native Settings and capture entry points are desktop-only.
