P1, apps/mobile/src/state/threadOutboxDelivery.ts:661-665: the per-thread slot is released (dispatchingThreads.delete plus finishDispatchingQueuedMessage) as soon as the thread's queue is empty, even while that thread's startTurn (:370-401) is still in flight. Remove the in-flight head, then enqueue another message in the same thread: the new send starts before the first settles, so turns can reach the server out of order or concurrently.
Fix: the slot belongs to the in-flight send, not to the queue contents. Keep the thread's slot (marked "retiring") until that send's delivery promise settles, success or failure, and release it only then. An emptied or removed queue may cancel only a send that has not started yet, meaning the upload-wait phase. A startTurn already sent to the server is never abandoned to let another send start. Test, red first, with a held startTurn (Deferred): remove the in-flight message and enqueue a new one in the same thread; the new send does not start until the held one settles, and then it starts. Another thread is unaffected throughout.

Before recording a failure or retry, check that the message is still queued with the same identity; drop stale settlements.
