# U05 · Attachment extraction and transcript ingest

## C4 compatibility note written before implementation

- Older guest clients on a new host send the same multipart request and get the same response, guest message, and attachment metadata. The host uses its bounded DocumentText worker on the guest's staged copy. Only the existing provider attachment flow consumes the sidecar.
- Newer guest clients on an older host use the same request and response. A document still attaches and follows the older host's extraction behavior.
- Invalid or revoked sessions and stale share IDs are denied before publishing attachments. Existing guest type, count, byte and share-budget checks remain authoritative. Unsupported or malformed documents remain normal attachments without extracted text. A rejected submission removes its own staged attachments and sidecars independently.
- No migration or wire change. Old attachments and messages remain readable after upgrade or rollback. Extracted text uses the existing optional sidecar format and existing lifecycle ownership.
