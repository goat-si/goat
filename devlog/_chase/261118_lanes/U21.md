# U21 · OpenCode 1.x lifecycle

## #601 · C4 compatibility before implementation

- Older clients with the new server continue sending existing runtime modes and policies. OpenCode 1.x task children now inherit an explicit external-directory allow in the same no-approval unrestricted cases that already permit the root operation.
- Newer clients with the old server use the same wire schema. On the old server a full-access child's initial external-directory operation can still prompt before GOAT installs the inherited policy.
- Approval-based or granular policies retain their asks. Workspace-write remains scoped to configured roots, restricted read-only keeps external paths denied, and a native child deny and GOAT's task deny still take precedence.
- Upgrade and rollback use the existing `goatPermissionBase` metadata to replace the base on resume. Both versions recognize the same rule shape and retain native rules and the GOAT-owned task deny. No schema change or migration.

## #418 · C3 plan

- OpenCode 1.x SSE recognizes an unseen root prompt followed by native busy/retry. Hold a bounded sequence through late output, replay in native order on the existing ProviderContinuationService path, and bind continuation admission to its own message ID without sending a second native request.
- Serialize turn installation and replay with the native event reader. Foreground takeover preserves held output while excluding the prior execution from prompt admission. Stop, abandoned dispatch, transport closure and overflow release held work and reject stale ownership.
- Root work uses existing server run and projection contracts across web, desktop and mobile. Child tool/report and question routing stay on their owning session. No new entry point, setting, RPC, docs, or migration.
- Verify whole changed OpenCode adapter tests, OpenCode replay fixtures plus guarded server tests from apps/server, and the changed-files gate against the integration branch.
