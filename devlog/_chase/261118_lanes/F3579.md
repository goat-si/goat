## C4 compatibility before implementation

The owner accepted the original size increase and tracked deduplication separately in goat#3579, now consolidated into #3729. The accepted N10 D4 plan uses the packaged desktop web copy as the offline source for the three embedded POSIX SSH archives. The release CLI archives, native Windows SSH ZIP, and WSL archive stay full. N10 measured five faces at 34,818,280 bytes in the nightly .376 Linux CLI archive. Between .371 and .376 the published CLI tarball grew by 33.2 MB and the AppImage, dmg, and exe by 133.9, 134.6, and 163.5 MB respectively. Those installer deltas include every change between the two builds. The projected saving is three copies, 104,454,840 raw font bytes, before recompression.

- Older client with newer server: the existing SSH host selection, auth, version checks, server RPC and asset routes are unchanged. An already installed usable full runtime is reused. Older desktop packaging and old full bundles carry their own assets and need no optional payload. A browser paired directly to a trimmed host loads that host's own web bundle and same-origin font assets.
- Newer client with older server: an existing compatible runtime with its own client/assets remains untouched. A new install chooses only its exact bundled version. Host download, cache, mirror, published fallback and native Windows acquisition keep their prior behavior.
- Negative and authorization: the original 256 MiB runtime cap and checksum validation remain. The trimmed archive gets its own canonical SHA-256 sidecar and install record. Only the existing authorized bundled upload may send fonts. Source bytes are restricted to the exact generated asset basenames and verified by a manifest. The remote verifies the font payload before copying in the private runtime staging directory. Missing, mismatched or uncopyable fonts do not stop an otherwise valid install. Corrupt runtime bytes still stop it. The browser uses BetterOffice's bundled last-resort face after the CJK asset request fails and keeps the existing stalled-request deadline.
- Implementation touches desktop packaging, desktop/server SSH runner configuration, the shared SSH upload, and the Office font loader. No wire, schema, migration, dependency or provider change. The release packaging log reports the font bytes.
- Verification: fail the packaging, SSH install and browser regressions first, then run the changed test files whole and `vp run check:changed origin/chase/t3-261114-next3` after one integration merge. No dev server, release publication, or lane CI.
