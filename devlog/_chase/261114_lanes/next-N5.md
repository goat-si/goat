- Downgrade and second upgrade (rewritten for review N5-P3-1): dev opens only usage-scan-cache-v14.json and older names (dev usageScanCache.ts:21-22, UsageService.ts:403-404) and never opens usage-scan-cache-v15.json; with no v14 file left it rescans and writes its own v14 file, with correct figures (a v15 document is refused anyway, dev usageScanCache.ts:197). Dev never deletes the v15 file. After a stay on dev and a second upgrade, the head reads its own old v15 file first, coverage included, so the first provisional answer can be as old as that stay; it is marked refreshing and replaced by the exact read. Usage from transcripts created and deleted while on dev exists only in dev's v14 file, which the head deletes after its first save, so that usage is lost; earlier version bumps behaved the same way.
- `coveredSince` (7fab4ef978, no version bump): it lives in the v15 file only; dev never reads or writes that file. Coverage loads only from the current file name with every entry decoded (UsageService.ts:286, :296, :303), so a provisional answer never comes from an older or partly decoded file.
- UsageSummaryInput.provisional: an older server ignores the flag and scans in full (contract test with dev's field set; client test keeps that answer after one request); a newer server reads an older client's input as a plain, exact read (contract round trip; server test after a restart); a non-boolean flag is rejected.
- UsageLimitSourceSnapshot.origin and ServerProviderAuth.endpoint (packages/contracts/src/usageLimitEndpoint.test.ts): an older peer decodes both as absent; a newer peer reads an older snapshot without them; blank values are rejected. An older server sends no endpoint, so the fallback is not asked and the provider's own reset (null) stays.
