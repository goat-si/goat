# 10.011 — upstream Node 26.12.1 고정

> 사이클: 261022 · 상태: ✅ fin · P1 · GOAT 영역: `node-pin`, `cli-home` (010 참조)
> upstream: `ed9b7ca9c` (#23165) · devcontainer `52c2b38ea4` (#23808)
> Closed: 2026-10-25 PR #1587 (goat-si/goat, `chore/node-26-pin`)

## 무엇이 다른가

upstream은 루트 `package.json`의 `engines.node`를 정확한 `26.12.1`로 고정하고, 개발·CI·standalone 실행 파일이 모두 그 버전을 쓰게 했다.
`apps/server/vite.config.ts`의 `SEA_NODE_VERSION`을 지우고 `engines.node`를 읽으며, 네이티브 실행 파일 빌드는 다른 host Node를 거부한다.
`release-desktop.yml`과 `docs/operations/release.md`도 그에 맞췄다. 결정 전 GOAT는 루트 `engines.node` `^24.16.0`, `SEA_NODE_VERSION` 26.8.2였다.

서버 패키지의 `engines.node`는 upstream과 GOAT 모두 `^22.16 || ^23.11 || >=24.10`였다. 이 범위의 24.16·26.1 이전 Node는
`node:sqlite`가 TEXT를 첫 NUL에서 자른다 (#1015, nodejs/node#61954). 데스크톱은 서버를 `ELECTRON_RUN_AS_NODE`로 Electron 44의
Node 24.22.0에서 돌린다 (`apps/desktop/src/backend/DesktopBackendConfiguration.ts`).

## 결정

adapt (사용자 결정 2026-10-25). Node 26을 받는다.

- 루트 `engines.node`는 정확한 `26.12.1`이고 개발·CI·SEA의 유일한 정본이다. `setup-vp`·`setup-ci-deps` 캐시 키·`vp`가 읽고,
  SEA cross-target `nodeVersion`과 `scripts/dev-runtime-archive.ts` fallback도 읽는다. 워크플로의 `VP_NODE_VERSION: "26.8.2"`와
  `SEA_NODE_VERSION`은 지웠다. 실행 파일 Node는 26.8.2에서 26.12.1로 오른다.
- 서버 `engines.node`와 `nodeSqliteClient.ts`의 런타임 검사는 `^24.16.0 || >=26.1.0`이다 (#1015 option 1). Electron 44의
  Node 24 때문에 26 전용으로 좁히지 않는다. `@types/node`도 24로 둔다.
- upstream의 네이티브 빌드 guard(host Node ≠ `engines.node`면 throw)는 받지 않았다. `dev-runtime-archive`가 SEA를 지원하는 다른 Node를 일부러 고른다.
- 고정 이전 커밋(`^24.16.0`)을 다시 빌드하는 stable 승격·수동 실행은 Node 24가 `--build-sea`를 거부하므로,
  `release-desktop.yml`·`goat-nightly.yml`의 실행 파일 단계가 정확한 버전이 아닌 `engines.node`를 보면 workflow revision의
  `package.json` 고정값을 `VP_NODE_VERSION`으로 넘긴다.
- devcontainer는 upstream `52c2b38ea4`처럼 Node 26이다.
