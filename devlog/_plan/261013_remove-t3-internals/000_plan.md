# 000 — Remove internal T3 traces (T2 roadmap)

GOAT still carries upstream T3 Code's internal names: the `@t3tools/*` package scope (3,234 files), `T3CODE_*`/`T3_*` env vars (~200 names), `~/.t3` and `.t3` data paths, `t3code:*` storage keys, `t3.json`, `t3-*://` URIs, eight `t3-*` mobile native modules, the `oxlint-plugin-t3code` lint plugin, and many `T3*` identifiers. This unit renames everything GOAT owns to GOAT names. Each name that carries user data or user configuration keeps a fallback or migration. External contracts and attribution stay unchanged.

Bundle: T2 (merges last, after S1 upstream sync and T1 visible branding). Branch `chore/remove-t3-internals-r2` from origin/dev `4ed8d2739`. Draft PR until S1 and T1 land.
Research: `001_inventory.md` (three gpt-6.1-sol read-only lanes: env, persisted data, packages/tooling).

## Loop spec

- Archetype: satisfy-spec, multi-cycle. wp1 is this docs-only roadmap; each later work-phase is one PABCD cycle and one or more small commits.
- Goal: no GOAT-owned identifier, package, env var, path, or storage key uses a T3 name. Existing user data and configuration keep working. A rename tool reproduces the mechanical part after every upstream sync.
- Non-goals: user-visible strings, docs prose and comments (T1), `.repos/`, devlog history, upstream-owned disabled workflows, T3 Connect relay vocabulary, upstream attribution and LICENSE files.
- Verifier per cycle: targeted `vp test run` for touched tests, targeted typecheck/lint for touched packages, `node scripts/goat-rename.ts --check` residue report, independent gpt-6.1-sol review. Final: all goat-ci jobs green locally and on the PR.
- Stop: every work-phase done with fresh evidence and S1/T1 merged and rebased, or a blocker needing a human decision.
- Escalation: anything that would rewrite live `~/.goat` or `~/.t3` state, publishing, marking the PR ready before S1/T1 merge.

## Decisions

| ID  | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Reason                                                                                                                                                                                          |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Mechanical renames are produced by `scripts/goat-rename.ts`: an ordered table of explicit rules (token or regex → replacement, path scope) plus file and directory moves. It is idempotent and has `--apply [--only <category>]`, `--check` (fails on T3 tokens that are neither renamed nor on the keep list) and `--list`. No blanket `t3`→`goat` replacement.                                                                                                                                                                                                                                          | The branch must be regenerated after S1 lands, and every future upstream sync brings new T3 names. A reviewed rule table is reproducible; hand edits are not.                                   |
| D2  | Branch layout: script-output commits first (one per category, message `chore(rename): [script] <category>`, body = exact command), hand-written commits after. On rebase, drop the script commits, rerun the script on the new base, then cherry-pick the hand commits.                                                                                                                                                                                                                                                                                                                                   | Script commits never need conflict resolution; hand commits stay small.                                                                                                                         |
| D3  | All legacy T3 spellings that compatibility code must still read live in one excluded module, `packages/shared/src/legacyT3Names.ts` (and its test). The script skips it; everything else imports the constants.                                                                                                                                                                                                                                                                                                                                                                                           | Keeps the rename idempotent and makes every compat path greppable from one place.                                                                                                               |
| D4  | Package scope `@t3tools/*` → `@goat/*`; workspace package `t3` → `goat` (bins `goat` and legacy `t3` kept); generated `@t3code/t3-<platform>` → `@goat/cli-<platform>`; `t3code-relay` → `goat-relay`; `oxlint-plugin-t3code` → `oxlint-plugin-goat` with rule ids `goat/*`. Lockfile regenerated with `vp i`.                                                                                                                                                                                                                                                                                            | All are private or build-local in GOAT: goat-nightly publishes only GitHub releases to goat-si/goat-releases, and npm/AUR workflows are disabled upstream files.                                |
| D5  | Env vars: GOAT-owned `T3CODE_X` → `GOAT_X`, `T3_X` → `GOAT_X`. One `adoptLegacyEnv` runs first in every entry point (server bin, desktop main, dev-runner, scripts with their own env reads) and copies a legacy value into the GOAT name only when the GOAT name is unset. Child-env scrub lists cover both prefixes. User-authored project scripts get both `GOAT_PROJECT_ROOT` and `T3CODE_PROJECT_ROOT` (same for `WORKTREE_PATH`). Installed boot units and launchers keep working because adoption also runs in the service launcher.                                                               | One adoption point covers Effect `Config`, `process.env` and `HostProcess.Environment` readers without per-site fallbacks. Dual emission is the only way to keep existing user scripts working. |
| D6  | Env vars that belong to T3 Connect (`T3CODE_CLERK_*`, `T3CODE_RELAY_*`, `VITE_T3CODE_RELAY_URL`, `T3CODE_HOSTED_APP_URL`, relay OTLP vars, `T3CODE_WEB_*` domains) stay.                                                                                                                                                                                                                                                                                                                                                                                                                                  | Their values come from the upstream relay's generated env files; renaming would split one contract.                                                                                             |
| D7  | Server default home `~/.t3` → `~/.goat`. When neither `GOAT_HOME` nor `--base-dir` is set, `~/.goat/userdata` is absent and `~/.t3/userdata` exists, the server keeps using `~/.t3` and logs once. Worktree dev home `.t3` → `.goat` with the same rule. No copying.                                                                                                                                                                                                                                                                                                                                      | Copying a live SQLite database while upstream T3 may be using `~/.t3` on the same machine is unsafe; continuing to read the old root orphans nothing.                                           |
| D8  | `t3.json` → `goat.json`: read `goat.json` first, else `t3.json`; writes go to whichever file exists, and to `goat.json` when neither does. The repo's own file is renamed.                                                                                                                                                                                                                                                                                                                                                                                                                                | Project files are checked in and may be shared with upstream T3 users of the same repository.                                                                                                   |
| D9  | Browser localStorage/sessionStorage keys `t3code:*`/`t3code.*` → `goat:*`/`goat.*` through one storage helper that reads new, falls back to old, writes new, and deletes old after a successful copy. Mobile SecureStore/AsyncStorage keys `t3code.*` → `goat.*` the same way. IndexedDB databases and the mobile `t3code-client.db` get a one-time copy on open with the old store kept until the copy succeeds.                                                                                                                                                                                         | Drafts, preferences, credentials and DPoP keys must survive.                                                                                                                                    |
| D10 | Wire/persisted identifiers GOAT owns: write new and accept old. `t3-thread://`, `t3-context://`, `t3-citation://`, `t3_context`, `data-t3-context-fragment` and the clipboard MIME get dual parsers. `/.well-known/t3/*` and `x-t3-orchestration-protocol` are served under both names; clients try the new path and fall back. Session cookies `t3_session*` are accepted, and new ones issued as `goat_session*`. Checkpoint refs: write `refs/goat/checkpoints`, read both. Theme ids `t3-chat`/`t3-code` translate on load. Metrics `t3_*` → `goat_*` (operator dashboards must follow; noted in PR). | Event history and older peers keep working without a database rewrite.                                                                                                                          |
| D11 | SSH runner: shell variables `T3_*` → `GOAT_*` and `run-t3.sh` → `run-goat.sh`. A new client still recognizes and replaces an existing `run-t3.sh` runner and parses its `T3_*` assignments. The runner byte change triggers one managed restart, which the existing RUNNER_CHANGED path already handles.                                                                                                                                                                                                                                                                                                  | Runners persist on remote hosts across versions.                                                                                                                                                |
| D12 | Must stay: T3 Connect relay vocabulary (`x-t3-relay-*`, `x-t3-hook-outcome`, relay JWT ids, `t3-connect`/`t3_relay` connection kinds, app.t3.codes); `pingdotgg/t3code` attribution links and the upstream schema URL; `LICENSE*`, `THIRD_PARTY_NOTICES`, `UPSTREAM.md`; external client identities (Codex `clientInfo`, ChatGPT agent hint, Cursor/OpenCode session names); the terminal snapshot magic `T3VT`; `.repos/`; `devlog/` history; upstream-owned disabled workflows. Each lands on the `--check` keep list with a reason.                                                                    | External services own these, or they are binary/attribution contracts.                                                                                                                          |
| D13 | Desktop identity that keys stored secrets stays for now: the Electron runtime name `T3 Code` (keys the macOS Keychain "Safe Storage" entry) and the `t3code://` renderer origin (keys all desktop localStorage/IndexedDB). Renaming them needs a decrypt/re-encrypt and cross-origin storage migration inside Electron; that is a separate follow-up issue.                                                                                                                                                                                                                                               | High risk of silently losing saved credentials; not a code-identifier problem.                                                                                                                  |
| D14 | Dead code: remove unreferenced upstream marketing concept images after a reference check. AUR packaging, relay infra and disabled workflows are upstream-owned and stay (renamed only where GOAT code depends on them).                                                                                                                                                                                                                                                                                                                                                                                   | Deleting upstream-owned files creates modify/delete conflicts on every sync.                                                                                                                    |
| D15 | Comments, docs prose and visible strings belong to T1. The script still renames identifiers that appear inside comments (for example an import path in a doc comment).                                                                                                                                                                                                                                                                                                                                                                                                                                    | Avoids double work and keeps T2 conflicts with T1 to identifier lines.                                                                                                                          |

## Applying the renames on a future upstream sync

1. Before merging upstream tag `U`: `git switch -c upstream-renamed/U U && node scripts/goat-rename.ts --apply && git commit -am "chore(rename): [script] upstream U"`.
2. Merge `upstream-renamed/U` into dev instead of the raw tag. Both sides already carry identical renamed lines, so only real conflicts remain.
3. After resolving, run `node scripts/goat-rename.ts --apply` again (idempotent) and `--check`. New upstream T3 names either match an existing rule or fail `--check`; add a rule or a keep-list entry with a reason.
4. New upstream persisted keys or env vars need a compat entry in `legacyT3Names.ts` if existing data must carry over; otherwise the rule is enough.
