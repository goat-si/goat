BEHAVIOR (required):
1. Gate `makeReaderAdmission({ limit, timeout: Duration | null, honorFailFast })` is an Effect run in the client's make scope. It captures that Scope. Default limit 64, timeout from new config `readerAdmissionTimeout?: Duration.Input` (default 30 seconds; must be finite and ≥ 0, else die like readerPoolSize validation; 0 = never wait).
2. Single synchronous `pump()` runs on every arrival and every release. It grants tokens to the oldest queued waiters while held < limit. Arrival = enqueue then pump, so there is no barging. Waiters whose monotonic deadline has passed (now >= deadline) are expired, never granted, except that a just-arrived waiter is considered for an immediate grant in the same synchronous step before its deadline is checked. So with timeout 0 a read is admitted at once when it is at the queue head and capacity is free, and fails as overload only when it would have to wait. Tests: timeout 0 with free capacity admits; timeout 0 when saturated fails at once with overload; timeout 0 behind an older queued waiter fails at once (no barging).
3. Waiter state moves exactly once: queued → granted | expired | cancelled | closed. Invariant: held = admitted owners + granted-not-yet-resumed, and held ≤ limit. Each token is released exactly once.
4. Deadline: captured at request with `Clock` monotonic time (same source as nodeSqliteClient.ts `acquired()`). Each queued waiter has a timer forked with `Effect.forkIn(timer, clientScope, { startImmediately: true })`. The timer sleeps the remaining time, then calls expire (fail the waiter's Deferred with ReaderAdmissionOverloadError) only if the waiter is still queued. Expiry finishes normally. Grant/cancel interrupt the stored timer handle (fork the interrupt, do not join synchronously). After storing the handle, recheck the state and interrupt if already settled. The deadline fires even for an uninterruptible caller.
5. Caller await: `(restore ?? identity)(Deferred.await(d))`, where restore = TransactionAcquire pending.restore in the transaction path, else the ReadOnly reference value (sqliteReadRouting.ts). onExit of the await: if it failed or was interrupted while state is granted → release the token (passes it on via pump); if queued → remove and mark cancelled.
6. Grant before the deadline is owned even if the fiber resumes after it (no claim-time recheck).
7. Fail-fast: `FailFastReaderAdmission` Context.Reference (default false) + `failFastReaderAdmission(effect)`. When honorFailFast and the reference is true and no token is free → fail overload immediately (do not enqueue).
8. Scope close: a finalizer settles every queued waiter as closed with `ReaderAdmissionClosedError` (new class). It is not an overload; isReaderAdmissionOverload stays false for it.
9. Errors to SqlError: a single exported `admissionSqlError(cause)` builds the SqlError ("Database reader overloaded" for overload, "Database client closed" for closed, operation "acquire") using the same classification that `classifyError`/`failed` in nodeSqliteClient.ts produce. The SqlError for overload must still satisfy `isReaderAdmissionOverload`.
