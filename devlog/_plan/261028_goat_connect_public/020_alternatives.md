# 020 대안 비교

확인일 2026-10-28. 외부 근거 원문은 각 연구 레인 보고서(아래 "출처")에 URL과 확인일로 남겼고, 여기에는 결정에 쓰인 수치와 대표 URL만 옮깁니다. 구현량은 코드 분석에 따른 판단입니다(S: 기존 HTTP/WS를 그대로 쓰고 설정만 추가, M: 새 커넥터나 서비스 하나, L: 서버·공유 클라이언트·모바일에 걸친 새 전송, XL: L + 테넌트 운영).

## 먼저 나눠야 할 것

Connect가 하는 일은 셋입니다(010 마지막 절). 대안은 대부분 **도달(reachability)** 하나만 바꿉니다.

| 기능                             | 터널 필요    | 지금 GOAT의 대체 경로                                                               |
| -------------------------------- | ------------ | ----------------------------------------------------------------------------------- |
| 어디서나 도달                    | 예(현 설계)  | Tailscale 페어링과 허브(docs/user/remote-access.md:20-57, :574-599), SSH, 서버 링크 |
| 고정 공개 URL(웹훅, 게스트 링크) | 현 설계는 예 | 없음                                                                                |
| 모바일 백그라운드 알림           | 아니오       | 없음(docs/user/mobile-notifications.md:1-8)                                         |

어떤 전송도 잠든 머신을 깨우거나 푸시·오프라인 웹훅을 대신하지 못합니다. 그래서 relay의 계정·푸시·웹훅 부분은 어느 대안을 고르든 남습니다.

## 판단

1. **환경마다 관리형 터널을 무료로 주는 모델은 공개 서비스로 권하지 않습니다.** 공급사가 막는 것은 아니고 경제성 판단입니다. 비용이 사용량이 아니라 "등록된 머신 수"에 비례하고, 1,000개를 넘는 순간 사용자당 월 $4.05~$6.30이 고정으로 붙습니다. Cloudflare 약관 2.2.1(j)의 VPN·프록시 제한 해석도 확인되지 않았습니다(030, 040).
2. **GOAT에는 이미 허브가 있습니다.** 휴대폰이 허브 하나에 붙으면 노드는 허브가 대신 연결합니다(remote-access.md:574-599). 관리형 터널을 쓰더라도 **사용자당 1개, 허브로만**이 GOAT에 맞는 단위입니다. 그러면 무료 구간이 1,000명이 되고 초대 베타는 터널 비용 $0으로 끝납니다. 두 가지 전제가 있습니다. 첫째, 지금 Connect 세션에는 `hub:proxy` 권한이 없어(apps/server/src/cloud/CloudLink.ts:1629-1634, packages/contracts/src/auth.ts:175-194, apps/server/src/hubProxy/http.ts:185-186) 허브 소유자가 이 권한을 승인·회수·재발급하는 경로를 만들어야 합니다. 표준 권한 전체에 넣는 방식은 피합니다. 둘째, 허브 경유는 채팅 작업까지만 됩니다(packages/contracts/src/hubProxy.ts:31-74). 노드의 터미널·설정은 노드 자신의 경로가 필요하고, 노드의 게스트 링크와 웹훅은 그 노드의 Connect 주소가 있어야 동작합니다(apps/server/src/guest/GuestShareService.ts:313-326, infra/relay/src/hooks/HeldHooks.ts:60-75).
3. **공개 단계의 유력 후보는 Durable Object WebSocket relay + E2EE입니다.** 양쪽이 바깥으로만 연결하므로 포트·DNS·터널 프로비저닝이 없고, 비용이 DO가 깨어 있는 시간에 비례하며, 같은 Cloudflare Worker 안에서 운영됩니다. 마스터 키 위험을 줄이는 것은 암호화가 아니라 **권한 구조 변경**입니다. 환경이 로컬에서 승인한 기기 공개키와 권한을 보관하고, 새 기기 추가·복구에 relay 로그인과 독립된 승인을 요구하며, 기존 mint 경로(CloudLink.ts:1597-1634)를 끄거나 약한 옵션으로 격리해야 합니다. 서명 키만 가진 공격자가 만든 새 기기가 거부되는지가 출시 조건입니다. 범위에는 브라우저 웹 앱을 어디서 내려줄지(서명된 네이티브 앱과 매번 받는 웹 코드는 신뢰 보장이 다름), HTTP·파일·WebSocket 대응, 무계정 게스트의 권한 전달이 들어갑니다. 구현량이 가장 크므로 공개 단계에 맞춰 준비하고, 노드별 유료 터널·BYO 터널과 실측 비용으로 다시 비교합니다.
4. **공개 URL은 도달과 따로 풉니다.** 웹훅은 relay Durable Object가 받아 보관하고, 호스트가 바깥으로 연결해 가져가게 합니다. 기존 hold 저장소·크기 제한·delivery ID는 재사용하지만, 공개 URL 키와 소유권 조회가 터널 할당에 묶여 있고(docs/internals/goat-connect.md:21-37, infra/relay/src/hooks/HeldHooks.ts:60-100) 현재 서비스는 hold/wake/clear만 있어(infra/relay/src/hooks/HookInbox.ts:18-32) 새 전달 프로토콜입니다. 터널과 독립된 endpoint ID, 환경 인증 fetch/ack, 재전달·순서·삭제, 발신자에게 돌려줄 응답(202 또는 동기), 기본 저장 여부를 정해야 합니다. 게스트 링크는 relay 경로가 생기면 그 위로 갑니다. 사용자 소유 터널·Funnel URL을 공개 주소로 입력받는 선택지도 둡니다.
5. **Tailscale은 계속 1급 경로로 둡니다.** 이미 구현돼 있고 비용이 0이며 종단 간 암호화됩니다. Connect는 "Tailscale을 설치하기 싫은 사람"과 "푸시·웹훅이 필요한 사람"을 위한 것으로 범위를 좁힙니다.
