# 010 현재 구조 분석

확인 기준: 브랜치 `docs/goat-connect-public-research`, 기준 커밋 `3a2b1e8036`(2026-10-28). 모든 근거는 저장소 경로와 줄 번호입니다.

## 한 줄 요약

dormant Connect는 "한 운영자가 운영하는 다중 사용자 relay"로 설계되어 있고, 사용자별 소유권 검사·터널 개수 제한·웹훅 레이트 리밋·터널 회수까지 이미 있습니다. 공개 서비스로 막히는 지점은 코드 구조보다 **운영 범위**(사용자마다 우리 Cloudflare 계정에 터널과 DNS 레코드를 만드는 방식), **가입 통제가 Clerk 대시보드 설정뿐**이라는 점, 그리고 **T3 시절 설정과 문서**입니다.

## 데이터 모델 (Postgres)

infra/relay/src/persistence/schema.ts 기준 테이블 10개입니다. 사용자 수에 비례하는 것은 `relay_mobile_devices`(:20), `relay_live_activities`(:45), `relay_environment_links`(:65), `relay_managed_endpoint_allocations`(:90), `relay_managed_tunnel_limits`(:122)입니다. `relay_environment_credentials`(:129)는 환경 수와 재링크 횟수에 비례합니다. 재링크마다 새 행을 넣고 이전 행은 지우지 않고 revoke합니다(infra/relay/src/environments/EnvironmentCredentials.ts:128-163). 활동량에 비례하는 것은 `relay_agent_activity_rows`(:151, 30분 뒤 종료 상태 정리 worker.ts:409-414), `relay_delivery_attempts`(:167, 정리 경로는 code-audit 참조), `relay_dpop_proofs`(:194, 만료 정리 worker.ts:403-405)입니다. 사용자당 환경 2개, 추적 스레드 10개, 보존 정책이 있다는 가정에서 1만 명 약 0.3~0.7GB로 추정됩니다(030 참조). 무제한 기기·환경, 쌓이는 revoked credential, 끝나지 않은 활동 행은 이 추정을 벗어나게 합니다.

## 공개 서비스 관점에서 이미 갖춘 것

- **사용자 경계.** 클라이언트 경로는 검증된 토큰의 `sub`만 userId로 씁니다(infra/relay/src/http/Api.ts:341-346). 환경 측 요청은 해시된 환경 bearer 자격이 환경 ID와 공개키로 풀리고 그 키의 활성 링크가 있어야 통과합니다(Api.ts:353-379). 그 위에 터널 복구는 서명된 `environmentId`·`cloudUserId`·`action`을 대조하고(Api.ts:603-609), 활동 발행은 별도 서명을 검사합니다(Api.ts:1185-1194). 링크·할당 테이블의 기본키가 `(userId, environmentId)`라서(schema.ts:85, :109) 남의 환경 행을 같은 키로 덮을 수 없습니다.
- **relay가 세션을 보지 않음.** relay는 bootstrap 자격을 중개만 하고 환경 세션 토큰은 받지 않습니다(goat-connect.md:52-57). 트래픽도 relay를 지나지 않습니다(goat-connect.md:17-20).
- **SSRF 방지.** 엔드포인트는 relay 자신의 할당에서만 찾고, 리디렉트를 따르지 않습니다(goat-connect.md:73-78).
- **동시성.** 할당마다 `generation`을 두어 회수와 재연결 경쟁을 막습니다(goat-connect.md:100-105, :143-146).
- **Cloudflare API 429 공유 일시정지.** 한 isolate가 429를 받으면 전체가 멈춥니다(schema.ts:115-120).

## Connect가 실제로 제공하는 것 (세 가지로 나뉨)

Connect를 켜면 사용자는 세 가지를 얻습니다. 이 셋은 서로 다른 인프라를 쓰므로 따로 출시할 수 있습니다.

1. **어디서나 도달.** Tailscale 없이 휴대폰·브라우저가 집 머신에 붙음. 터널이 필요한 유일한 기능입니다.
2. **고정 공개 URL.** 웹훅 수신(goat-connect.md:21-26)과 게스트 링크(docs/user/guest-links.md:9-11)는 공개 주소가 있어야 합니다.
3. **모바일 백그라운드 알림.** 푸시와 Live Activities는 relay가 있어야 하고(docs/user/mobile-notifications.md:1-8), 터널과는 무관합니다. 서버에는 이미 터널 없이 링크하는 `publish_only` 모드가 있고(apps/server/src/cloud/CloudLink.ts:895), 이 경우 relay는 터널을 만들지 않습니다(infra/relay/src/environments/EnvironmentLinker.ts:290-311).

GOAT에는 이미 Tailscale 페어링과 허브(docs/user/remote-access.md:20-57, :574-599, docs/user/hub.md:1-10), SSH 호스트, 서버 간 링크가 있어 1번의 대체 경로가 있습니다. 2번과 3번은 지금 대체 경로가 없습니다. 이 분리가 020과 000의 추천을 결정합니다.
